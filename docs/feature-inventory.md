## A. 需求与协作（Intake & Collaboration）

| ID | 功能 | 说明 | 阶段 | 来源/痛点 |
|---|---|---|---|---|
| A1 | 需求/任务/缺陷管理 | 工作项全生命周期管理，事件驱动状态流转（backlog→todo→in_progress→done/blocked） | P1 | 基础 |
| A2 | 服务目录 | 所有服务的统一目录：负责人、文档、健康度、依赖图；领域模型轴心 | P1 轻量版 | Backstage / 痛点6 |
| A3 | 角色化工作台 | PM/开发/QA/运维四种首页视图，同一平台按角色呈现 | P1 | 易用性 |
| A4 | IM 通知与审批卡片 | 钉钉/企微/飞书/Slack：流水线事件通知（P1）、发布审批卡片（P2 完整版） | P1→P2 | Devtron |
| A5 | 自动 Release Notes + Lead Time | 从事件流自动生成本版本包含的需求/PR/提交；需求到生产周期自动计算 | P2 规则版 / P3 增强 | 痛点7 |

## B. 开发与代码（Develop）

| ID | 功能 | 说明 | 阶段 | 来源/痛点 |
|---|---|---|---|---|
| B1 | Git 深度集成 | GitHub/GitLab 接入，PR/MR 驱动一切，构建与部署状态自动回写 | P1 | 基础 |
| B2 | PR 评审 | 规则评审（P1）→ AI 代码评审（缺陷/安全/风险识别，P2） | P1 / P2 | Zadig |
| B3 | 黄金路径脚手架 | 新服务生成器，组织最佳实践内置，从模板一键创建项目 | P3 | Backstage |
| B4 | TechDocs | docs-like-code，文档跟服务走 | P3 | Backstage |
| B5 | CLI + API-first | Web 与 CLI 共用同一套 API，一切能力可自动化 | P1 | 开发专家 |

## C. 测试（Test）

| ID | 功能 | 说明 | 阶段 | 来源/痛点 |
|---|---|---|---|---|
| C1 | 测试管理 | 用例管理、测试计划、自动化测试框架集成（pytest/JUnit/Playwright 等） | P2 | 测试专家 |
| C2 | 质量门禁 | 覆盖率阈值、扫描卡点、可编排的通过策略 | P2 | 测试专家 |
| C3 | 镜像安全扫描门禁 | Trivy 构建时扫描漏洞，作为流水线默认步骤 | P1 | Devtron |
| C4 | 智能测试选择 | 基于服务目录依赖图 + 历史事件推荐该跑哪些测试；规则版先行 | P2 规则版 | 痛点5 |
| C5 | 失败自动归因 | 测试/流水线失败日志 AI 分析，区分环境问题/Flaky/真实缺陷 | P2 | 测试专家 |

## D. CI/CD 与发布（Build & Release）

| ID | 功能 | 说明 | 阶段 | 来源/痛点 |
|---|---|---|---|---|
| D1 | 工作流引擎 | DAG 编排、Job 插件协议、`agent` Job 类型（与构建/部署同框编排） | P1 | Zadig |
| D2 | 模板库 | 构建/部署/流水线模板跨项目共享，批量接入微服务，YAML 与可视化双向同步 | P1 | Zadig |
| D3 | 环境管理 | 面向服务的环境：一套服务配置派生多套环境，面向不同角色 | P1 | Zadig |
| D4 | 渐进式交付 | 金丝雀/蓝绿/Istio 灰度编排，发布可观测、可回滚 | P2 | Zadig |
| D5 | 关联物回滚 | 发布登记变更关联物清单（镜像+配置+开关+迁移），回滚按清单逆向执行；DB 迁移仅提示不自动执行 | P3 | 痛点4 |
| D6 | 高并发构建部署 | 多服务并行构建/部署，Job 队列调度 | P2 | Zadig |
| D7 | Onboarding Wizard | 引导式接入：连 Git → 导入服务 → 自动识别语言生成配置 → 跑通首条流水线 | P1 | 易用性 |
| D8 | PR Preview 环境 | PR 级临时环境一键拉起/销毁，闲置自动休眠控成本 | P2 | 测试专家 |

## E. AI 层（AI Layer，基于 dsh 融合）

| ID | 功能 | 说明 | 阶段 | 来源/痛点 |
|---|---|---|---|---|
| E1 | LLM 多模型可插拔 | DeepSeek/OpenAI/Claude/国产模型统一接入，企业可自带 Key | P2 | 核心决策 |
| E2 | dsh 零分叉融合 | agent-gateway 边界接口 + 契约测试升级门禁 + 版本锁定，随上游更新 | P2 | 核心决策 |
| E3 | 全局 AI 侧边栏 | 任何页面可对话："分析发布风险"、"为什么测试挂了" | P2 | 前端专家 |
| E4 | AI 风险摘要审批卡 | 审批人看到：变更范围、影响服务、测试通过率、历史回滚记录，而非一个按钮 | P2 | 痛点3 |
| E5 | 上下文 AI 诊断 | 全链路事件作为 Agent 上下文，诊断质量由上下文质量决定 | P2 | 痛点2 |
| E6 | 目录问答 Agent | 对服务目录的自然语言问答（"这个服务怎么部署？"），RAG 事件流与文档 | P3 | 痛点6 |

## F. 平台底座（Platform）

| ID | 功能 | 说明 | 阶段 | 来源/痛点 |
|---|---|---|---|---|
| F1 | 事件溯源 + 变更指纹 | 全链路不可变事件流，traceId 贯穿需求→PR→构建→发布→运维；**架构级差异化地基** | **P1** | 痛点1 |
| F2 | RBAC + SSO | 细粒度权限（Casbin 类模型）；OIDC 单点登录；多租户 P3 | P1 / P3 | 运维专家 |
| F3 | 审计日志 | 全操作可追溯 | P2 | 安全 |
| F4 | Web 调试三件套 | Web 日志查看 + K8s 资源浏览器 + Web 终端 | P2 | Devtron |
| F5 | 特性开关 | 部署≠发布：逐步放量、kill switch、A/B、过期 flag 提醒 | P2 | Unleash |
| F6 | DORA 四指标看板 | MTTR、变更失败率、部署频率、变更体量 | P2 | DevLake/Devtron |
| F7 | 配置漂移检测与 reconcile | 跨环境配置比对，一键修复 | P3 | Devtron |
| F8 | External Secrets 集成 | 密钥不落库，对接外部密钥管理系统 | P3 | 运维专家 |
| F9 | SLSA 供应链 + FinOps | 制品溯源证明；环境成本视图 | P3+ 候选池 | Harness |
| F10 | 双形态交付 + Demo 模式 | Helm Chart（企业）+ Docker Compose（小团队）+ 一键演示数据 | P1 | 运维/易用性 |
| F11 | ⌘K 命令面板 | 全局搜索与跳转：任意服务/环境/流水线可达 | P1 | 易用性 |
