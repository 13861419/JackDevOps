# JackDevOps 操作手册

> 面向所有角色（PM / 开发 / 测试 / 运维）。每一步都对应平台里真实可点的操作。

## 1. 快速开始

### 1.1 启动

```powershell
# 在仓库根目录执行（会自动启动 API + 前端 + 播种演示数据）
powershell -ExecutionPolicy Bypass -File scripts\start-local.ps1
```

启动成功后：

| 入口 | 地址 |
|---|---|
| 控制台（浏览器打开） | http://localhost:5173 |
| 局域网同事访问 | http://<本机IP>:5173 |
| API | http://localhost:3000 |

登录：**默认免登录**（开发者身份）。要配置多用户见第 9 节。

### 1.2 一分钟上手流程

1. 打开控制台首页 → 点 **「开始上手」** �一遍向导
2. 或直接点左侧 **「服务目录」** → 注册你的第一个服务
3. 在 **「流水线」** 给服务建一条流水线 → 点运行
4. 到 **「运行记录」** 看执行轨迹，点 **「AI 风险摘要」** 让 AI 帮你分析

## 2. 控制台（首页）

打开即见全局视图：服务数、流水线数、运行记录数、部署频率、Lead Time、失败率、MTTR、成本。

- 任意页面按 **Ctrl+K**（Mac：⌘K）打开命令面板，输入关键词可跳转任意服务/流水线
- 右下角 **AI 助手悬浮按钮**：用自然语言提问，例如「为什么上次的发布失败了？」「现在有多少个服务没有测试？」

## 3. 服务目录

**作用**：所有微服务的统一档案（负责人、语言、仓库地址）。

### 注册服务
1. 左侧导航 → **服务目录**
2. 表单填 **服务名称**（slug 自动生成）→ 选语言 → 点 **「注册服务」**
3. 服务出现在下方列表

### 注意
- 名称重复会提示冲突；slug 也可在 API 里显式指定
- 每个服务可关联 `repoUrl`（Git 仓库），供 PR 评审/状态回写使用（API 传入）

## 4. 需求与任务

**作用**：管理需求（requirement）、任务（task）、缺陷（bug），状态机：backlog → todo → in_progress → done / blocked。

- **新建**：填标题 → 提交
- **状态流转**：点列表中的工作项 → 点状态按钮（如「就绪」）
- **关联**：工作项可关联到服务，发布时自动追溯「这次上线包含了哪些需求」

## 5. 流水线

**作用**：DAG 编排的流水线，一个 workflow 属于一个服务。

### 内置 Job 类型
| 类型 | 作用 |
|---|---|
| build / test / deploy | 执行 shell 命令（fail-closed：命令失败即流水线失败） |
| scan | Trivy 安全扫描门禁（装了 trivy 才执行） |
| container-build | 真实 docker build（可选 push） |
| agent | 调 DeepSeek Agent 自主完成任务（需 DEEPSEEK_API_KEY） |
| 市场插件 | npm-audit / prettier-check / secret-scan / helm-lint（见第 8 节） |

### 创建与运行
1. **流水线** → 新建流水线（名称 + 选服务）
2. 定义 jobs（示例：build → test → deploy，test 依赖 build）
3. 点 **「运行」** → 自动跳到运行记录

### 配置示例（jobs 的 config）
```
build:  { "command": "npm test" }
container-build: { "image": "myapp", "tag": "latest", "context": "." }
agent:  { "task": "审查本次变更并给出风险等级" }
```

## 6. 运行记录（含 AI）

每次运行保存完整事件链（traceId 贯穿）。

- **查看 trace**：运行列表 → 点 run_ 链接，看到每个 Job 的 started/succeeded/failed 事件
- **AI 风险摘要**：点按钮，AI 阅读完整事件链后输出给发布审批人的风险摘要（需要 LLM 配置，见第 9 节）
- **AI 诊断**：流水线失败时，AI 区分真实缺陷 / 环境问题 / Flaky 测试，并给下一步建议

## 7. 预览环境

**作用**：每个 PR 自动/手动拉起一个隔离的真实环境。

1. **预览环境** → 填服务 slug + PR 编号 → **手动创建**
2. 点 **「部署」** → 真实拉起容器（本机 Docker 或 K8s 集群，自动探测）
3. 浏览器打开生成的 URL 验证
4. 点 **「回收」** 销毁（PR 关闭时也会自动回收）

## 8. 插件市场

**作用**：给流水线安装现成的质量门禁。

```
GET    /market                # 查看目录与安装状态
POST   /market/:slug/install  # 安装（slug: npm-audit | prettier-check | secret-scan | helm-lint）
DELETE /market/:slug          # 卸载
```

安装后，`npm-audit` 等就是合法的 Job 类型，可直接写进流水线 spec。

## 9. 常见配置（环境变量）

| 变量 | 作用 | 不配会怎样 |
|---|---|---|
| JACK_ADMIN_TOKEN | 管理员令牌 | 默认 dev-admin-token（仅限本地） |
| JACK_LLM_BASE_URL / JACK_LLM_API_KEY / JACK_LLM_MODEL | AI 功能（摘要/诊断/Copilot） | AI 按钮返回 503 |
| JACK_LLM_MAX_TOKENS | 默认 4096（推理模型建议 ≥4096） | 过小会返回空内容 |
| JACK_GITHUB_TOKEN | Git 状态回写、AI 评审拉 diff | 回写/评审跳过 |
| DEEPSEEK_API_KEY | agent Job 与 AI 评审 | agent Job 优雅跳过 |
| NOTIFY_PROVIDER + NOTIFY_WEBHOOK_URL | 审批卡片推送（钉钉/飞书/企微/Slack） | 卡片不发送 |
| JACK_PREVIEW_BACKEND | docker / k8s / stub | auto 自动探测 |

## 10. 常见问题

**Q：运行记录显示 failed，怎么排查？**
运行详情里有完整事件 trace；点「AI 诊断」让 AI 帮你区分是代码问题还是环境问题。

**Q：流水线命令在哪里执行？**
在服务进程的工作目录（容器内/宿主机）。绝对路径或先 checkout 仓库再执行。

**Q：AI 功能报 503？**
说明 LLM 没配置。用 `scripts\start-local.ps1` 启动会自动读取本机 `.dsh` 凭证；或手动设置 JACK_LLM_* 环境变量。

**Q：数据会丢吗？**
默认内存模式，重启即清空（演示用）。生产用 `deploy/docker-compose.yml`（PostgreSQL 持久化 + Redis 队列）或 Helm Chart 部署到 K8s。
